# Память проекта

Обновлено: 2026-10-28.

## Задание (track.md)

Трек «О!дин шаг до идеального отеля»: агентная система для Островка — собирать характеристики отелей/номеров из открытых данных и от отельеров, хранить с источником/уверенностью/датой, искать по свободной фразе. Минимум одна **вычисленная гео-характеристика** (не угадывание LLM). Диалог с отельером, конфликты источников, расширяемость через рецепты YAML. Прототип на одном регионе, демо-данные в репо, запуск по README.

## Концепция (concept.md)

Продукт: **Досье стороны** / Hotel Fact Agent. Регион: Патриаршие и Садовое кольцо. Объект: отель → сторона здания → факты. Ядро гео: пеший путь до якоря (OSM), луч видимости и солнце по стенам (OSM), шум стороны (дорога + ночной POI). Карты-микросервисы: Базовая (снимок Островка), Корпус, Вид, Экология, Путь, Город, Развлечения, Шопинг, Дежурство, Зал. В снимке сейчас по сути OSM + `nightclubs.json` / `shops.json`; data.mos.ru в концепции для гостиниц и театров, воздух/«Дежурство»/«Зал»/ремонты метро — источник назван, **снимков нет** (`metro_repairs.json`, `facts.json` в репо нет). Три отеля в демо: Пекин, Safmar, Lotte.

## Решение Greg (2026-10-27)

Текущий прототип кажется **слишком простым** для жюри; акцент организаторов — **геоданные для гостя**, не «ещё один чат». Рассматриваем обогащение: **data.mos.ru** (приоритет), investmoscow.ru (контекст), um.mos.ru (культура/якоря).

**FAQ-агент отельера:** TF-IDF для шаблонных `section:*`; fallback **vector RAG** (MiniLM + FAISS, upload-чанки). Гость `/api/faq/hotels/pekin/ask`: `method` = `rag_tfidf` | `rag_vector`. Демо: `python -m hotel_faq.demo_rag_pekin --ask "…"`. Uvicorn: `backend`, порт 8080.

**База:** SQLAlchemy 2 и Alembic. Модели в `backend/common/tables.py`, сессия `common.database.session_scope` / `get_db`, миграции `backend/alembic`. Первая ревизия `c4a8e1b07d22`. Счета, брони, сообщения и FAQ идут через `Session`. Факты сторон в `common/db.py` пока на `sqlite3`. Новая схема — только новая миграция.

**Окружение:** каталог `.venv` в корне (не `venv`), в `.gitignore`. Python 3.12.4: `.\.venv\Scripts\python.exe`. Активация: `.\.venv\Scripts\Activate.ps1`. Зависимости из `backend/requirements.txt`. Весь локальный запуск: `.\run.ps1`. Шлюз :8080, страница Vite :5173, агенты: geo 8081, view 8082, noise 8083, mobility 8084, events 8085, hotelier 8086, conflict 8087, search 8088, hotel_faq 8092. Описание для жюри: `README.md` в корне. Vite проксирует `/media` на шлюз, чтобы карусель брала фото из `media/pictures`.

## Дальше

Питч: не четыре фичи, а досье стороны — чего нет в карточке отеля. Посчитано: контур и азимут, луч и солнце, шум окружения у стены, путь и закрытый выход метро. Чего не посчитали — «не знаем». Отельер отвечает из базы и не стирает расчёт. Скринкаст после готового продукта: презентация, по ней видео, затем README для жюри. Жюри запускает проект без ключа. Свободный ответ после оплаты: `GigaChat-2`, если в `.env` есть `GIGACHAT_AUTHORIZATION_KEY`. Ключ Greg положил 2026-10-28, в git его нет. Без ключа гость получает фразу из фактов. Число вне снимка гостю не показывается. Вызов DeepSeek из кода убран. Неизвестный вопрос после оплаты идёт в `GigaChat-2`, вопрос про тихую сторону отвечает снимком и не подменяется куском базы. Обновление страницы в кабинете клиента оставляет кабинет: адрес `?account=guest-N` открывает тот же счёт, бронь и чат. «На главную» убирает этот параметр, и следующее обновление остаётся на главной. Переписка главной в адресе не хранится. В чате кабинета вопрос про парк и стадион подписан «Ответ · снимок окрестностей». Фраза «Я выбираю Пекин» отвечает фактами отеля (минуты, тихая сторона, солнце) и регистрацией, либо «бронь уже оплачена», если счёт уже оплачен. Свободный ответ GigaChat на эту фразу не вызывается. Если модель дописывает тему к «этого в снимке нет», гостю остаётся фраза из снимка. В списке входа остался один гость: «Админ Островка» (`ostrovok-admin`). Старые счета, брони и сообщения удалены 2026-10-28. Новая регистрация «Григорий» получает пустой счёт. В чате кабинета у сообщения есть «Удалить у меня» и «Удалить у меня и у отельера» (`hidden_for_guest` / `hidden_for_hotelier`, миграция `e6b1c4a90d33`).
