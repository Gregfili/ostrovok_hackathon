# Hotel Fact Agent

Прототип трека «О!дин шаг до идеального отеля» (хакатон Островок).

Рабочее имя продукта — **Досье стороны**. Гость описывает поездку своими словами. Система не выдумывает карточку: она показывает посчитанные факты о **стороне здания** (улица или двор), в которую человек будет смотреть все ночи. Чего нет в снимке или в ответе отельера, в ответе стоит «не знаем».

Регион демо: Патриаршие пруды и Садовое кольцо. В снимке три отеля: **Пекин**, **Safmar Grand Moscow**, **Lotte Hotel Moscow**.

Слоган на странице: «Создай свой островок».

Подробности: `doc/concept.md` (продукт), `doc/architecture.md` (сервисы), `doc/structure.md` (каталоги), `doc/track.md` (постановка).

## Скринкаст

Скринкаст с обзором приложения будет добавлен после готового демо. Ролик записывается по презентации и выкладывается на общедоступный хостинг с просмотром без входа.

## Модель

Проект запускается без ключа. Контур, луч, солнце, шум окружения и пеший путь считает код по снимку. На известный вопрос гость получает эту фразу. Если факта в снимке нет, ответ: «этого в снимке нет».

Неизвестный вопрос после оплаты может пересказать **GigaChat-2**, если в `.env` есть `GIGACHAT_AUTHORIZATION_KEY`. Файл в git не входит. Без ключа программа не останавливается и не ждёт ключ от жюри: остаётся фраза из снимка. С ключом модель получает только эти факты. Ответ с числом, которого в фактах нет, гостю не показывается.

## Что можно посмотреть

1. Диалог на главной. С первой фразы отели не предлагаются: сначала даты, затем цель поездки (отдых или командировка), и только потом три отеля.
2. Справа выдача: фото, две стены, солнце на стену на даты заезда, пешая доступность. Под каждым отелем кнопка «Выбрать» — то же, что фраза «Я выбираю Пекин».
3. Регистрация кнопкой в правом верхнем углу: новый счёт или вход в уже существующий. До оплаты открываются дополнительные карты (экология, шопинг, развлечения, здоровье). «Оплатить» пишет бронь, карта не нужна, деньги не списываются. После оплаты можно спрашивать по отелю и открыть чат с отельером.
4. Кабинет отельера: регистрация отеля и ответ на вопрос гостя из уже посчитанного снимка.

Вычисленная гео-характеристика, не текст модели: пешие минуты до якоря, луч видимости по контурам соседних зданий, сектор солнца на стену, оценка шума стороны по классу дороги и ночному заведению рядом. Это не замер децибел в номере и не свет внутри комнаты.

## Архитектура

Снаружи одна дверь — шлюз **Hotel Fact Agent**. Страница ходит только в него. Внутри каждый агент — свой процесс FastAPI со своим `GET /health`. Шлюз собирает ответ по рецептам YAML и не содержит формул луча, шума и пешего пути.

```text
Страница (Vite :5173 или собранный frontend/dist)
        │
        ▼
gateway :8080  Hotel Fact Agent
        │
        ├── geo        контур, сторона, азимут
        ├── view       луч по зданиям и солнце на стену
        ├── noise      дорога и ночной POI у стены
        ├── mobility   минуты пешком, магистраль, закрытый выход метро
        ├── events     снимок закрытых выходов метро
        ├── hotelier   вопрос и разбор ответа отельера
        ├── conflict   два значения одного факта, ответ отельера не стирает OSM
        ├── search     слоты фразы и фильтр по фактам
        └── hotel_faq  чат отельера: TF-IDF и векторный поиск по загруженным текстам
```

Факты посчитаны заранее и лежат в `backend/data/`. На запросе гостя живыми остаются разбор фразы, фильтр и один пеший путь. Сеть на старте не ходит в Overpass и data.mos.ru.

База — один файл SQLite `backend/data/app.db`. Схема описана моделями SQLAlchemy (`backend/common/tables.py`) и применяется миграцией Alembic при старте шлюза. Счета, брони, переписка и FAQ читаются через `Session`. Факты сторон в `common/db.py` пока остаются на `sqlite3`.

## Структура

```text
ostrovok_hackathon/
  run.ps1                 запуск страницы, шлюза и всех агентов
  run.py
  README.md
  doc/                    постановка, концепция, архитектура

  backend/
    gateway/              публичный API и страница на защите, :8080
    geo/ view/ noise/ mobility/ events/
    hotelier/ conflict/ search/ hotel_faq/
    admin/                счета гостя и отельера, бронь
    dialogue/             реплика гостю
    common/               факт, снимки, SQLite, SQLAlchemy, Alembic
    alembic/              миграции
    recipes/              YAML характеристик
    data/                 снимки OSM, магазины, клубы, базовая карта Пекина
```

У каждого агента есть `service.py` (расчёт) и `main.py` (отдельный процесс). Рецепты: `facade_visibility`, `facade_noise`, `walk_to`, `metro_exit`, плюс `pets.yaml` без гео-инструмента — поле пустое, пока не ответит отельер.

## Запуск

Нужны Python 3.12 и Node.js. Команды из корня репозитория, PowerShell.

Окружение называется `.venv` (с точкой). Каталога `venv` в проекте нет.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd frontend
npm ci
cd ..
.\run.ps1
```

`run.ps1` поднимает всё и открывает страницу. Остановка: Ctrl+C в том же окне.

| Что | Адрес |
|---|---|
| Страница в разработке | http://127.0.0.1:5173 |
| Шлюз, API и картинки | http://127.0.0.1:8080 |
| geo | http://127.0.0.1:8081/health |
| view | http://127.0.0.1:8082/health |
| noise | http://127.0.0.1:8083/health |
| mobility | http://127.0.0.1:8084/health |
| events | http://127.0.0.1:8085/health |
| hotelier | http://127.0.0.1:8086/health |
| conflict | http://127.0.0.1:8087/health |
| search | http://127.0.0.1:8088/health |
| hotel_faq | http://127.0.0.1:8092/health |

Vite проксирует `/api`, `/health` и `/media` на шлюз, поэтому в браузере один адрес. Шлюз стартует первым: он применяет миграцию, и FAQ не открывает ту же базу одновременно.

Активировать окружение в текущем окне PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -c "import sys; print(sys.executable)"
```

После активации `python` — это интерпретатор из `.venv`. Без активации тот же интерпретатор вызывается явно:

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
```

Если скрипт активации блокирует политика PowerShell, для одного окна достаточно:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

На защите наружу публикуется только 8080. Шлюз отдаёт собранную страницу:

```powershell
cd frontend
npm run build
cd ..\backend
..\.venv\Scripts\python.exe -m uvicorn gateway.main:app --host 127.0.0.1 --port 8080
```

Страница: http://127.0.0.1:8080

## Публичный API шлюза

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | шлюз и агенты |
| POST | `/api/search` | фраза гостя → диалог и отели |
| GET | `/api/hotels/{id}` | стороны и факты |
| POST | `/api/hotels/{id}/hotelier` | ответ отельера |
| POST | `/api/walk` | один живой пеший путь |
| GET | `/api/quality` | метрики на размеченной выборке |
| POST | `/api/admin/pay` | бронь прототипа, без списания |
| POST | `/api/faq/hotels/{id}/ask` | вопрос в чат отельера после оплаты |
| GET | `/media/pictures/...` | фото отелей и карусели |
